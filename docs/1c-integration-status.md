## Выгрузка данных

Исходный модуль: `backend/integrations/onec/ExportModule.bsl`.
Он только читает справочники через объектную модель 1С и пишет JSON в локальный
файл. Документы, регистры, номенклатура и рецептуры обработкой не изменяются.
Доступность выполнения и чтения всех данных учебной платформой ещё не проверена.
Остатки и движения регистров в этот экспорт не входят.

Сборка из каталога `backend`:

```powershell
.venv/Scripts/python.exe -m scripts.build_1c_export `
  --platform 'C:/Program Files (x86)/1cv8t/8.3.27.1508/bin/1cv8t.exe' `
  --database '../.devdata/1c-integration/upr' `
  --output '../.devdata/1c-integration/upr-data.json' `
  --build-dir '../.devdata/1c-integration/export-build' --user 'Администратор'
```

Сборка внешней обработки прошла успешно. Это ещё не проверка выполнения BSL.
Запуск: `ENTERPRISE /F <локальная база> /N Администратор
/RunModeManagedApplication /Execute <путь к KaravayExport.epf>`.
Режим управляемого приложения позволяет избежать обычного стартового интерфейса
старой бухгалтерской конфигурации. Предупреждение безопасности 1С подтверждает пользователь.

После создания JSON выполнить из `backend`:

```powershell
.venv/Scripts/python.exe -m scripts.analyze_1c_export `
  '../.devdata/1c-integration/upr-data.json' `
  --report '../.devdata/1c-integration/upr-analysis.json'
```

Следующие шаги: проанализировать записи и единицы измерения, выбрать действующие
рецептуры (не выбирать автоматически при нескольких спецификациях), реализовать
сопоставление стабильных ссылок 1С с UUID приложения, выполнить пробный импорт
и сверку. Затем проверить повторный импорт без дубликатов и доступ через API.

Наличие восстановленного файла `1Cv8.1CD` само по себе не является подключением
приложения к 1С. PostgreSQL приложения остаётся отдельной базой по архитектуре
`docs/presentation.md`.
